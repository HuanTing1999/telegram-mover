Telegram 搬运工作台 · Windows 64位图形界面

双击同目录的 TelegramMover.exe，打开软件窗口，无需安装 Python、无需操作终端。
软件有“搬运任务 / 广告过滤 / 发送限速 / 运行记录”四个页面。

首次使用：
1. 应用凭证由整款软件共用，不是每个手机号一套。已配置时会自动读取，日常不用再填写。
   软件尚未配置时，在“应用设置”填写一套有效的 API_ID 和 API_HASH 并保存，只需配置一次。
   可点击“申请应用凭证”打开 Telegram 官方 my.telegram.org/apps。
   已设置系统环境变量时，运行优先使用环境值，窗口会提示。
2. 输入带国际区号的手机号（菲律宾 +63…、美国 +1…、英国 +44…、香港 +852… 等），点击“发送验证码”。
   支持号码中的空格、括号、连字符和 00 国际前缀，不会自动添加国家码。
   账号区域会立即显示连接/验证码进度；缺少 API 凭证或网络错误也直接显示在这里，可点击“停止当前操作”。
   收到验证码后输入，按回车或点击“验证并登录”；不会自动发送或提交验证码。
   已登录过可点击“恢复已有会话”。不接受 Bot Token、二维码或第三方登录。
   账号若已开启两步验证，验证码通过后会按需提示输入该账号的两步验证密码；未开启则不询问。
   密码按原样验证，前后空格属于密码；密码不写入配置、账号列表或日志。成功后仅保存授权session。
   换其他账号请点击“添加账号”；已有账号可从账号列表选择并点击“切换账号”。
   各账号独立保存登录状态，换号不改应用凭证，也不会删除原来的会话。
3. 填写源频道/群及目标，选择正文模式和是否同步评论。
   支持频道链接和完整帖子链接（含t.me/c私有帖子链接）、@用户名或数字ID。
   帖子链接仅识别所属频道，起点仍按起始ID与已保存进度。也可点击输入框旁“选择”，搜索当前账号已加入的频道/群组。
   只读预览只要求源，不必先填写目标。
4. 在“广告过滤”页调整规则，点击“测试这段内容”离线试算，或预览最近消息查看判定。
   确认后点击“开始搬运”。安全停止会等正在发送的媒体组保存完映射，不强制中断。

验证码输错或没有收到：
- 输错后可重新输入正确验证码，也可在等待结束后点击独立的“重新获取验证码”按钮，不会自动循环发码。
- 账号区域显示 Telegram 实际返回的发送渠道；发到“Telegram 官方客户端”时，要查看该账号已有设备中的 Telegram 服务消息，不代表已发手机短信。
- Telegram 没有提供下一发送渠道或暂时禁止重发时，会明确提示；可以取消本次登录后重新申请，服务器等待仍需遵守。
- 取消、过期或连续输错会清除旧请求状态，保留已有登录会话。已进入两步验证密码步骤时请继续输入密码，无需再取验证码。
- 验证码通过后，醒目的“第2步 · 两步验证密码”区域会取代手机号和验证码输入；填写你在 Telegram 设置的密码即可，不用等重发倒计时。取消本次登录可回到第一步。
- 倒计时只对应本软件当前发码请求的重发等待，不是验证码或密码有效期，也不要求与官方客户端另一次请求同步。
- Telegram 要求的等待会保存在会话目录旁，关闭重开软件不重置；网络异常不会自动反复请求验证码。

点击开始后没有看到目标内容：
- 查看统计下方的任务状态卡：连接、解析频道、检查评论区、读历史、下载、上传、等待均显示当前步骤。
- 按钮恢复可点击时，状态卡会保留本次完成或失败原因；每次任务的日志单独显示，不再混淆旧登录错误。
- 处理0条时会说明是否没有新增内容、起点超过最新消息、还在相册稳定等待期，或内容被广告规则屏蔽。
- “等待1秒：最小请求间隔”是正常读取间隔，不代表已经发送；纯下载模式也不会向目标发送内容。
- 只读请求等待约45秒无响应会报出具体步骤；历史分页另计配置的分页间隔。下载连续120秒无字节进度会停止，已有映射保留。
- AUTH_RESTART属于Telegram验证码服务的授权重启提示。本次请求会有限重试；最终失败时清理本次挑战并提示稍后手动重新获取验证码，不删除已有会话或搬运进度。
- 发送中点击停止会等待本组返回并保存结果；连接异常后的发送结果不明会保留待核对记录，避免自动重复发送。

简洁布局与输入：
- 登录成功后自动收起手机号、验证码和两步验证密码区域，保留账号选择栏；添加账号或管理登录时再展开。
- 数字、时间和下拉设置不会因鼠标滚轮而改变，滚轮只滚动页面；数值仍可键盘输入或点击上下按钮调整。
- 频道选择列表只读取当前账号可见聊天，包含归档群/频道，不自动加入新群，也不发送消息。

群组话题：
- 点击源/目标旁的“选择”，先选带话题的群，再在第二层选择综合、资源区等具体话题。
- 源也可选整个群/所有话题，目标可选默认位置；整个群会合并消息发到所选位置，不自动复制创建话题结构。
- 第二层确认后才更新群和话题；取消保留原选择，主界面可查看所选范围。
- 各话题范围独立保存进度；同群只能在不同明确话题之间搬运，不能把整个群搬回本群。
- 频道评论区与群组话题是两种功能，分别配置；帖子链接只识别父聊天，限定话题请用选择器。

下载文件夹与清理：
- 默认下载到 EXE 旁的 downloads；主任务页点击“选择文件夹”可选其他硬盘，“打开”可查看当前实际目录。
  相对路径以当前配置文件所在目录为准。点击“保存配置”或开始任务后保存目录设置，下次继续使用。
- “下载留档后转发”会先把本条消息或整个相册的媒体下载到所选目录，全部下载完成后才转发原消息。
- “一键清理已转发文件”只清当前目录中、本工具登记且已确认完成“下载留档后转发”的媒体。
  “转发成功后自动清理本次下载文件”默认关闭，只在此模式生效，仅处理本次成功转发的下载。
- 未发送、失败、待确认（pending）、被修改或未登记的文件保留；重传和纯下载备份文件保留。
  清理不删除消息映射、同步进度或待确认记录，数据库会保留文件历史与清理审计。
- 换目录用于新消息和未完成下载，不会自动移动旧文件或重跑已完成消息；清理旧目录请先选回对应目录。
- 旧版下载记录若缺少文件校验信息，会保留并提示人工核对，不会仅凭文件名和大小清理。
- 起始消息 ID、循环间隔和会话位置可在“高级设置：起点、循环与会话”中调整。

下载速度：
- EXE已包含原生媒体加解密加速，无需另装组件；下载时显示真实MB/s和已完成大小。
- 完整本地备份可复用；实际传输速度仍取决于网络和Telegram服务端，发送限速继续生效。
- 大文件默认4路受限并行读取；“高级设置 → 下载并行数”可设1–8，1为普通单路。小文件、照片、未知大小或CDN媒体按原下载方式处理。
- 并行读取保留相册顺序，整组完整下载并检查长度后才转发；调整并行数不重跑历史，不提高发送额度。
- ChatForwardsRestrictedError是源聊天开启“保护内容”，不允许直接转发，与下载速度无关。软件会提前检查并明确提示，不自动改成重传；需选择允许转发的源或由源管理员调整设置。

发送结果待核对：
- 普通转发/文字确认最多等待90秒；上传连续120秒没有实际进度才停止，长文件有持续进度可继续。
- 结果无法确认时保留整批待核对记录，并断开原连接，不自动重发。明确的权限/内容保护拒绝会显示具体原因。
- 打开“运行记录 → 待核对发送”，在目标手工核对并清理这批可能已发送的整组内容后，选中记录并勾选声明，再解除本地阻塞。
- 解除不会删除目标消息或立即发送，历史映射/进度/配额保留；下次运行才继续未完成内容。列表变化需刷新，部分映射不允许直接解除。

广告过滤规则：
- 组合检查正文、媒体说明、文件名、隐藏链接、按钮文字和按钮链接。
- 支持关键词、正则、域名黑名单、白名单，以及可选的全部链接/按钮拦截。
- 默认不会仅因有普通链接就拦截；预览中显示每条消息的判定原因。
- 相册任一成员命中就跳过整组，避免乱序或遗漏相册成员。
- 在预览中选中消息，点击“屏蔽所选消息/相册”可手动屏蔽，手动优先于白名单。
- 运行记录可查看已屏蔽内容和原因；修改规则不会自动重发已跳过的历史消息。
- 无图片/视频内容OCR识别，不保证覆盖所有广告。先预览可减少误拦截。

默认限速：发送操作至少间隔15秒；滚动60秒20条、1小时200条、24小时1000条。
正文、评论一起计数，相册按成员数计数。本次运行最多200条、60分钟。
可在“发送限速”页修改时段、配额和间隔。计数、冷却及账号停止原因持久保留。
这些是本机策略，不是 Telegram 官方安全上限，不能保证账号不受限制。

会话与数据：
- 根目录 config.toml 保留软件设置，窗口中保存即可，无需手动编辑。
- 默认 data 保存用户session、消息映射、拦截与限速记录，downloads保存媒体；相对路径按当前配置目录解析。
- 数据库 downloads 保存最新下载记录，download_files 保留各目录文件历史、清理状态、时间与错误审计。
- 手机号、验证码和两步验证密码不写入配置或账号索引；API_HASH、session和数据文件请保存在本机，不要分享。
- 普通频道评论区不支持原生直接转发，软件提供评论重传或纯备份。
